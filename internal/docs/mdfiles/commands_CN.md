# 命令分词与可执行目标选择

命令直接解析，不经过 Shell；环境变量、通配符和 `~` 保持字面量，不支持 Shell
重定向。每个管道段在临时赋值之后都必须显式以 `moonx` 开头。
引号用于组合参数，不会启用变量展开。

## 路径基准速查

区分启动目录、文档目录、块工作目录和模块目录：

| 对象 | 路径基准 |
| --- | --- |
| `check`、`test`、`update` 的输入路径 | mooncram 的启动目录。 |
| 本地模块的 `moon.mod` | 直接位于启动目录，不向父目录搜索。 |
| 未指定 `#cwd` 的用例 | 规范 Markdown 文件的父目录。 |
| `#cwd(path)` 中的相对路径 | 规范 Markdown 文件的父目录。 |
| 脚本路径及程序使用的相对文件参数 | 当前块的工作目录。 |
| 本地包完整名称 | 模块源码根目录（`moon.mod` 中的 `source`，默认模块根目录）；本地构建从模块根目录运行。 |

“规范”指解析符号链接后的真实路径。因此，通过文件符号链接选中的 Markdown 使用
链接目标的父目录。绝对路径无需基准。`#cwd` 只影响当前块，不改变模块查找位置，
也不改变其他块的 `#cwd` 基准。文档中任何用例执行前，所有声明的目录就必须存在。

例如，目录结构如下：

```text
project/
├── moon.mod                 # name = "user/acme"
├── cmd/tool/                # 本地可执行包
├── docs/
│   └── cases.md
└── fixtures/
    ├── read.mbtx
    └── input.txt
```

从 `project` 启动 `mooncram test docs/cases.md`。以 `#cwd(../fixtures)` 开头的块中，
`moonx ./read.mbtx input.txt` 选择 `project/fixtures/read.mbtx`，程序可以在
`project/fixtures` 打开 `input.txt`。不写该声明时，同一命令会查找
`project/docs/read.mbtx`，工作目录是 `project/docs`。

若该块改为运行 `moonx user/acme/cmd/tool input.txt`，起始围栏需声明
`mooncram user/acme`。模块采用默认源码根目录时，mooncram 使用 `project/moon.mod`
构建 `project/cmd/tool`，但程序仍在 `project/fixtures` 运行。
从 `project/docs` 启动 mooncram 会导致本地模块查找失败，`#cwd(../fixtures)`
不能修复这个问题。

## 命令语法

起始 `$` 之后的文本直接拆分为命令和参数，不经过 shell。
会处理引号和转义，但不展开环境变量。临时赋值仅在对应管道段的构建与运行中
覆盖继承的环境变量。报告和更新保留命令原文。

| 语法 | 含义 |
| --- | --- |
| 未加引号且未转义的 `\|` | 分隔管道段，两侧可以没有空格。 |
| 未加引号的空格或制表符 | 分隔参数，连续分隔符被忽略。 |
| `'text'` | 下一个单引号之前的内容均为字面量，反斜杠也不转义。 |
| `"text"` | 读取到下一个未转义的双引号。 |
| 单引号之外的反斜杠 | 将紧随其后的一个字符作为字面量，双引号内部也适用。 |
| `''` 或 `""` | 保留一个空参数。 |
| 相邻的引号片段与非引号片段 | 拼接为同一个参数，例如 `a"b"c` 变为 `abc`。 |
| `${NAME}` 或 `$NAME` | 普通文本，遵循与其他文本相同的分词、引号和转义规则。 |

反斜杠不解释 C 或 JSON 转义序列：单引号之外的 `\n` 表示 `n`，不是换行符。
末尾反斜杠或未闭合引号会导致解析错误。命令中不能嵌入 CR 或 LF。
Markdown 中的原始 NUL 会被替换为 `U+FFFD`（`�`）。

空管道段（包括开头或结尾的 `|`、`||`）会导致解析错误。引号内或转义的 `|`
是普通参数字符。例如支持：

```text
$ moonx ./producer.mbtx|moonx user/foo/cmd/filter|moonx ./consumer.mbtx
```

未引用且未转义的 `&`、`;`、`<`、`>`、反引号、`(` 和 `)`，无论出现在词的
哪个位置，都会被拒绝。所有管道段均不支持输出重定向，包括 `2>&1` 和
`1>/dev/null`。引用或转义后作为普通参数传入，例如 `'2>&1'`、`2\>\&1` 和
`1\>/dev/null`。不进行通配符展开、波浪号展开或命令替换。
`'$HOME'`、`*`、`~` 和 `'$(cmd)'` 均为字面量；未引用的 `$(cmd)` 因圆括号报错。
解析错误保留文档文件名和命令行号。

`#cwd(路径)` 声明当前块的工作目录。
声明独占一条逻辑行，以 `#cwd(` 开头、以最后一个 `)` 结束；中间全部文本作为非空路径。
不去空格、不分词、不转义、不展开变量，也不检查括号配对。
空格、反斜杠、引号、括号、中文及 `${NAME}` 均原样保留。
例如 `#cwd(../fixtures with spaces)` 无需引号；`#cwd("foo")` 的路径包含双引号，
`#cwd(a)b(c))` 的路径为 `a)b(c)`。每块最多声明一次，必须是第一条非空逻辑行，允许前导空行。
空路径、缺少结尾 `)`、重复声明及测试命令后的声明均报带源码位置的解析错误。
声明不接受预期输出或退出码，不计入用例数；仅含配置的块合法。
整次运行没有尝试检查或执行任何用例，也没有记录任何错误时，
报告 `ERROR no mooncram cases found`，以 `2` 退出，且不打印汇总。

以 `#cwd(` 开头的输出必须用 JSON 字符串加 `(escaped)` 表示，即使它不构成合法声明。
更新器自动转义此类输出，保证生成的文档能重新解析，再次更新不变。
更新时保留声明原文和 Markdown 排版。

工作目录配置只作用于当前块；没有声明时，用例使用规范 Markdown 文件的父目录。
相对 `#cwd` 路径也以该文档目录为基准，不受其他块的工作目录影响。
接受绝对路径和目录符号链接，并解析为真实绝对路径。脚本路径和程序的相对文件参数
使用块工作目录。本地模块仍从 mooncram 的启动目录查找，本地包从模块根目录构建。

执行该文档的任何用例或构建前，统一校验所有工作目录声明，
包括仅含配置的块。目录必须已经存在，不能由前面的用例创建。校验失败报一个文档
错误，定位配置行并显示解析后的路径；该文档执行零个用例且不更新，其他文档继续。
校验后目录被删除，则在使用该目录时产生执行错误。

不支持环境变量展开。`${NAME}`、`$NAME`、`${}`、`${A-B}` 和 `${UNCLOSED`
都是普通文本，不查询环境或校验引用格式。仍遵循通常的分词、引号和转义规则：
`${A B}` 分成两个参数，`"${A B}"` 则是一个字面参数。赋值值也遵循这些规则。
预期输出保持字面量。整篇文档解析成功后才会执行用例。

`$ NAME=value OTHER="${NAME}" moonx ./program.mbtx` 为一个管道段及其构建过程设置临时变量。
仅识别 moonx 之前连续出现的赋值，变量名和 `=` 必须未引用、未转义；
变量名必须匹配 `[A-Za-z_][A-Za-z0-9_]*`。值遵循命令的引号和转义规则，
可以为空或包含额外的 `=`。moonx 之后的赋值形式仍是普通参数。
`9A=x`、`A-B=x` 等含非法变量名的词不会被识别为临时赋值，而会按普通词处理；
若它们出现在 `moonx` 之前，会因缺少 moonx 前缀报错；位于目标之后则是程序参数。

临时值覆盖父进程环境，空字符串也会覆盖父环境。赋值值和参数均保持字面量：
`A=new B="${A}" moonx ./program.mbtx "${B}"` 将 `B` 设置为 `${A}`，并传入字面参数 `${B}`。
重复赋值以后者为准。各管道段的临时环境独立，后续命令继承父进程环境。
Windows 下变量名统一转为 ASCII 大写，匹配时不区分大小写；Linux 和 macOS 下区分大小写。
仅有赋值而没有命令会报解析错误。

每个可执行管道段跳过临时赋值后必须以 `moonx` 和非空目标开头。
缺少前缀、裸目标或空目标均为解析错误；目标之前不接受 moonx 选项。
目标路径、工作目录和文件参数中的变量形式文本保持字面量。
`export` 命令会报解析错误：`command must start with moonx: export`。

以 `.mbtx` 结尾的目标是本地脚本，相对于块工作目录解析，也接受绝对路径，
文件名可以包含 `@`。其他包含 `@` 的目标必须是带精确 SemVer 的远程坐标，
即使其包名与本地模块相同，也按远程包处理。

处理任何用例前，校验全部模块声明与启动 cwd 下 `moon.mod` 的 `name` 精确匹配，
包括仅含配置的围栏。配置缺失、无效或名称不符属于文档错误，定位到围栏起始行。
不向父目录搜索。

无版本包目标必须位于声明模块的围栏内，并写完整包名。
对于模块 `user/foo`，`user/foo` 精确选择根包，`user/foo/cmd/boo` 选择对应子包。
拒绝 `foo`、`cmd/boo`、其他模块名以及 `./foo` 等路径。
`source` 缺失、为空或 null 时使用模块根目录，否则源码根目录必须位于模块内。
完整包名相对于该源码根目录映射。包必须声明 `pkgtype(kind: "executable")`
或 `options("is-main": true)`；编译和后端错误直接传播。
路径穿越、空路径组件、嵌套 `moon.mod` 及符号链接越界均被拒绝。
无效的 `moon.pkg` 配置会报错。

任意二进制、shell 命令和 `.mbt` 文件不能作为目标，也不会通过 `PATH` 查找目标。
目标之后所有参数均原样传给程序，包括 `--`、`--version` 和 `--target`。
