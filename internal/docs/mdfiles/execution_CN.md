# 构建、执行、输出捕获与超时

## 执行范围与超时

`test`、`update` 和 `update --dry-run` 都会以调用者的权限，在用例工作目录中执行代码。
mooncram 不提供沙箱或临时工作区隔离。dry-run 禁止写入更新后的 Markdown，
但程序副作用和构建产物仍然可能产生。

`--timeout-ms` 默认为 `60000`。每个用例共用一个期限，覆盖路径检查、构建、远程获取、
执行和输出捕获，不会为每个子进程重新开始计时，也不是整次运行共用一个超时。

## 工具与后端

mooncram 使用外部 MoonBit 工具。构建本地用例需要 `moon`；脚本和远程包还需要 `moonx`，
Wasm 包需要 `moonrun`，原生包构建需要对应的原生工具链。
运行 mooncram 自身所用的后端，与用例选择的后端相互独立。

| 用例类型 | 后端 | 构建行为 |
| --- | --- | --- |
| `.mbtx` 脚本 | 始终为 Wasm | 先编译，再通过 `moonx` 执行。 |
| 本地包 | 默认为 Wasm；`--target native` 选择原生后端 | 执行前从本地模块构建。 |
| 远程包 | 始终为 Wasm | 管道段启动时，由 `moonx` 获取、构建和缓存。 |

脚本始终使用 Wasm，即使 CLI 指定了 `native`。
mooncram 按段顺序为每个用例的所有本地段请求构建，是否复用已有构建由底层工具决定。
只有所有本地段通过构建预检查后，才会启动任何被测程序。
脚本在运行 `moonx` 之前先进行编译预检查，因此预检查的编译失败不会被接受为
程序的预期退出状态。

构建失败或构建结果不可用属于工具执行错误，不能通过预期退出码 `[N]` 接受。
构建错误诊断包含构建的 stdout 和 stderr；成功构建的输出与被测程序输出分开，
不属于程序预期结果。

管道各段并发执行，系统管道将前一段 stdout 的原始字节传入后一段 stdin，
中间不进行解码或换行规范化。stdout 断言仅捕获最后一段的 stdout。
各段 stderr 并发读取并完整缓存，按段顺序拼接且不添加分隔字节，供诊断及
`@STDERR` 断言使用；无标记用例不匹配 stderr。所有捕获流都必须成功解码。
管道采用 pipefail：等待全部段结束，全部成功返回 `0`，否则返回管道位置最右侧的
非零状态，不受完成顺序影响。普通非零状态仍可通过 `[N]` 断言，后续用例继续。
远程包保留错误状态遵循下面的规则。没有可配置的输出大小上限，也不实时转发程序输出。

构建进程及每个管道段继承 mooncram 的环境，再覆盖该段的临时变量。
脚本构建预检查、远程 moonx 工具及本地包的构建和运行
使用同一份合并后的环境。工作目录是校验后的块配置目录，默认为规范文档的父目录。
构建进程和管道首段从 stdin 立即读到 EOF，不会读取 mooncram 的交互式输入。
后续段接收前一段 stdout。

捕获到的输出必须是有效 UTF-8。任一捕获流中出现无效 UTF-8 都会导致执行错误。
中间 stdout 字节保持未解码。
比较和报告前会把每个 CRLF 规范化为 LF。独立的 CR、NUL、ANSI 转义、行尾空格、
空行以及末尾是否有换行符，除此之外均保持有意义的差异。

## 超时与执行错误

到期后，以
`timed out after N ms (including build)` 报告执行错误。
直接管理的进程使用强制取消。启动或捕获错误也会取消所有已启动段，
退出时会关闭所有未消费的管道句柄。当前实现不保证清理脱离管理的后代进程或回滚其影响。
文件发现、文档解析、声明校验、报告和文档替换不在这个按用例计算的期限内。

仅远程命令将 `255` 和 `-1` 保留为执行错误，包括远程程序自身返回这些状态。
并发监视所有段的退出状态；任意远程段返回保留状态都会报错，包含坐标、
从 1 开始的管道段序号和状态码，并立即取消及回收其他进程。末段成功不能掩盖前段
保留错误，等待慢速前段也不能延迟发现后段错误。其他状态遵循上述 pipefail 规则。
保留状态、启动／捕获失败及超时均阻止整份文档
更新及生成试运行文档差异。

mooncram 不增加远程依赖安装或缓存机制。moonx 启动后负责获取、构建和缓存，
因此其他段可能在远程获取失败前已经运行并产生副作用；不保证获取失败前没有程序
副作用。远程获取与本地构建、执行共用已有用例期限。`test`、`update` 和
`update --dry-run` 使用相同执行流程。
