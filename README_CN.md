# mooncram

面向 MoonBit 命令行应用和脚本的简洁而强大的测试工具包。

## 快速开始

在本仓库目录中运行：

```text
moon run . -- test README.md
moon run . -- test examples
moon run . -- update examples --dry-run
```

下面是一个使用 [examples/hello.mbtx](examples/hello.mbtx) 的可执行示例：

```mooncram
$ ./examples/hello.mbtx "Moon Bit"
Hello, Moon Bit!
```

## 命令

```text
mooncram test [paths...] [--target wasm|native] [--timeout-ms N]
mooncram update [paths...] [--target wasm|native] [--timeout-ms N] [--dry-run]
mooncram --help
mooncram --version
```

两个命令都支持 `--color auto|always|never`（默认为 `auto`）。`NO_COLOR`
环境变量会禁用自动着色。全局选项可以放在子命令之前，也可以放在路径之后。
如果路径以 `-` 开头，请在它前面加上 `--`。

未指定路径时，扫描当前目录。对于目录，会递归查找其中的 `.md` 文件。
遍历目录时，在所有平台上都会跳过名称以 `.` 开头的条目、带有 Windows 隐藏属性的条目，
以及 `_build` 和 `target`。不会遍历目录符号链接。文件符号链接会被解析，
重复文件只运行一次。文件按规范路径排序后执行，用例按在文档中的顺序执行。
命令串行运行，彼此共享对文件系统的修改。

退出状态：

| 状态码 | 含义 |
| --- | --- |
| `0` | 所有断言通过，或更新／试运行成功完成 |
| `1` | `test` 中有一个或多个断言失败 |
| `2` | 参数无效，发生解析、构建或执行错误，或未找到任何用例 |

## 测试代码块

只有使用反引号围栏、且信息字符串为 `mooncram` 后跟可选空白的代码块才会被视为测试。
任何非空白尾随文本（包括旧版 JSON 配置语法）都会使整个围栏被静默忽略。
其他语言的代码块、波浪号围栏代码块，以及嵌套在更大示例代码块中的围栏也会被忽略。
支持引用块和列表中的测试。已识别但为空或未闭合的测试围栏会报错。

每个以 `$ ` 开头的行都会开始一个用例。命令必须指向已存在的本地 `.mbtx`
文件，或包含可执行 MoonBit 包（`is-main: true`）的目录。
本地包通过 `moon run --build-only` 构建，生成的产物在 Wasm 后端下通过
`moonrun` 运行，在原生后端下直接运行。构建诊断信息不会混入程序输出。
脚本会先通过仅构建调用进行检查，再通过 `moonx` 启动，因此编译失败不会被当作
程序的预期退出状态。无论 `--target` 如何设置，`.mbtx` 都使用 Wasm。

所有相对命令路径都以 Markdown 文件所在目录为基准，程序也在该目录下运行
（若文档为符号链接，则以解析后的实际文件为准）。
参数支持单引号、双引号和反斜杠转义。单引号内的内容按字面量处理；
在单引号之外，反斜杠会转义紧随其后的字符。引号包围的空参数会被保留。
不进行变量展开、通配符展开、波浪号展开或命令替换。
未加引号的 `|`、`&`、`;`、`<`、`>`、反引号和圆括号会导致错误。
如需将这些字符作为普通参数传入，请加上引号或进行转义。

````markdown
```mooncram
$ ./hello.mbtx 'Moon Bit'
Hello, Moon Bit!

$ ./cmd/main --version
my-cli * (glob)
```
````

命令后面的行描述预期输出。默认情况下，每一行都必须精确匹配，包括行尾空格。
末尾的 `[N]` 用于设置预期退出码；未指定时为 `0`。负数状态码表示程序被信号终止，
具体值由进程库报告。没有预期输出行意味着 stdout 必须为空。

代码块开头、结尾或紧邻下一条命令之前的空行用作分隔符。
非空预期输出行之间的空行则属于输出。要显式表示一个空输出行，请使用
` (equal)` 或 `"" (escaped)`，尤其是在输出末尾。
这样就能区分空输出和仅包含一个换行符的输出。

## 匹配与转义

| 后缀 | 含义 |
| --- | --- |
| 无后缀或 ` (equal)` | 精确匹配整行 |
| ` (glob)` | 整行通配符匹配：`*`、`?`、`[abc]`、`[a-z]`、`[!a-z]`、`[^a-z]`；反斜杠用于转义字符 |
| ` (regex)` | 使用标准库 `Regex` 进行整行匹配 |
| ` (escaped)` | 将 JSON 字符串解码后进行精确匹配，可表示控制字符 |
| ` (no-eol)` | 最后一行输出没有结尾换行符；位于其他后缀之后 |

通配符 `?` 和字符集合匹配单个 Unicode 字符。匹配过程中不会重复或跳过输出行。
未知括号后缀（如 `(foo)` 或 `(re)`）作为普通文本参与精确匹配。
格式错误的通配符或正则表达式，以及出现在非末行的 `(no-eol)` 都会报错，
并指出文件和行号。要按字面量匹配以已知注解结尾的输出，应使用 `(equal)` 或 `(escaped)`。

`(escaped)` 要求提供完整的 JSON 字符串。它可以表示制表符、回车符、NUL、
ANSI 转义序列，以及看起来像命令、围栏、状态码或匹配后缀的输出。
其中不能包含 LF（换行符）；请改用多个预期输出行。

````markdown
```mooncram
$ ./special.mbtx
"$ this is output" (escaped)
"[2]" (escaped)
"```" (escaped)
"\u001b[31mred\u001b[0m" (escaped)
"" (escaped)
final text (no-eol)
[3]
```
````

输出必须是有效的 UTF-8。比较时会将 CRLF 规范化为 LF；
独立的 CR（回车符）、空行、行尾空格和末尾换行符都会保留。

## 执行行为

不支持块级配置。`--target` 为所有本地包用例选择后端，`--timeout-ms`
为每个用例设置期限；`.mbtx` 脚本仍固定使用 Wasm。被测程序原样继承
mooncram 的环境，并从 stdin 立即读到 EOF。

预期结果始终与 stdout 比较。stderr 会与 stdout 并发排空以避免管道死锁，
并在断言失败时以 `diagnostic stderr` 显示。两个流都必须是有效 UTF-8，
且当前没有可配置的大小上限。

超时时间涵盖构建和执行。超时后，会取消直接管理的进程，并将该用例记为执行错误。
程序必须自行管理其脱离的子进程。测试以当前用户的权限执行本地代码，
不会在沙箱或隔离的临时工作区中运行。

## 更新预期结果

`update` 只修改未通过的预期结果。通过的用例和仍然匹配的模式会保留原样。
命令、围栏标记、容器前缀（如引用或列表前缀）、周围的正文以及文档的换行符格式都会保留。
特殊输出会被自动转义，缺少末尾换行符和非零退出状态也会被自动表示。

`--dry-run` 会运行相同的命令并显示文档差异，但不会写入 Markdown。
这些命令仍然可能对文件系统产生正常的修改。实际更新和试运行只要成功完成，
都会返回 `0`，即使存在需要修改的内容也是如此。

存在解析、构建或执行错误的文档不会被更新。其他文档仍然可以继续运行和更新。
写入更新之前，mooncram 会检查源文件内容是否发生变化，然后使用同目录下的临时文件
进行原子替换。替换后的文件使用新建文件的权限（`0644`，受 umask 影响）；
当前版本不会保留原文件的权限、inode 标识和扩展文件系统元数据。
