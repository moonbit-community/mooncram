# mooncram

面向 MoonBit 命令行应用和脚本的简洁而强大的测试工具包。

## 快速开始

在本仓库目录中运行：

```text
moon run . -- test README.md
moon run . -- test examples
moon run . -- update examples --dry-run
```

下面是一个使用 [examples/hello.mbtx](examples/hello.mbtx) 的可执行示例：

```mooncram
$ ./examples/hello.mbtx "Moon Bit"
Hello, Moon Bit!
```

## 命令

```text
mooncram test [paths...] [--target wasm|native] [--timeout-ms N]
mooncram update [paths...] [--target wasm|native] [--timeout-ms N] [--dry-run]
mooncram --help
mooncram --version
```

两个命令都支持 `--color auto|always|never`（默认为 `auto`）。`NO_COLOR`
环境变量会禁用自动着色。全局选项可以放在子命令之前，也可以放在路径之后。
如果路径以 `-` 开头，请在它前面加上 `--`。

未指定路径时，扫描当前目录。对于目录，会递归查找其中的 `.md` 文件。
遍历目录时，在所有平台上都会跳过名称以 `.` 开头的条目、带有 Windows 隐藏属性的条目，
以及 `_build` 和 `target`。不会遍历目录符号链接。文件符号链接会被解析，
重复文件只运行一次。文件按规范路径排序后执行，用例按在文档中的顺序执行。
命令串行运行，彼此共享对文件系统的修改。

退出状态：

| 状态码 | 含义 |
| --- | --- |
| `0` | 所有断言通过，或更新／试运行成功完成 |
| `1` | `test` 中有一个或多个断言失败 |
| `2` | 参数无效，发生解析、构建或执行错误，或未找到任何用例 |

## 测试代码块

只有使用反引号围栏、且语言名严格为 `mooncram` 的代码块才会被视为测试。
语言名后可加空白和一个模块名，例如 `mooncram user/foo`。声明仅作用于当前围栏。
多个词、旧版 JSON 配置和非法模块名会在围栏起始行报解析错误。
其他语言、波浪号围栏和更大示例围栏内的文本会被忽略。支持引用和列表中的测试。
空围栏或未闭合围栏会报错。

每个以 `$ ` 开头的行开始一条指令，除 `export` 外，每条指令开始一个用例。
普通 `mooncram` 围栏支持本地 `.mbtx` 脚本和文件导入别名。声明模块的围栏还支持该模块中的
可执行包。模块配置 `moon.mod` 必须位于 mooncram 的启动 cwd，声明必须与其
`name` 精确匹配。执行文档前校验所有声明，包括仅含 export 的围栏；不向父目录
搜索，本地模块声明也不加载注册表模块。

包位于模块 `source` 指定的源码目录下；未指定或为空时使用模块根目录。
对于 `user/foo`，`foo` 优先选择可执行根包，`cmd/boo` 选择 `user/foo/cmd/boo`。
根包不可执行时，`foo` 可选择可执行的同名子包 `user/foo/foo`。
可执行包通过 `pkgtype(kind: "executable")` 或旧的 `is-main: true` 声明。
双方可执行时选择根包，并为每个歧义管道段向 mooncram 的 stderr 输出一次
`WARNING`，包含文档位置、两个完整包名和选择结果。警告不参与匹配、更新或错误计数。
选中包构建失败或不支持目标后端时直接报错，不回退。包名不接受绝对路径、`./`、
`../`、路径穿越或嵌套模块。包配置使用 `moon.pkg`，兼容 `moon.pkg.json`；
配置解析失败会报错。

本地包通过 `moon -C <module-root> run --build-only` 构建，产物在 Wasm 后端下
通过 `moonrun` 运行，在原生后端下直接运行。构建诊断不会混入程序输出。
脚本先通过仅构建调用检查，再通过 `moonx` 启动；`.mbtx` 始终使用 Wasm。
脚本路径相对于 Markdown 目录解析，也接受绝对路径。所有程序都在 Markdown 文件
所在目录运行（符号链接以规范文件为准），即使模块位于其他目录。
参数支持单引号、双引号和反斜杠转义。单引号内的内容按字面量处理；
在单引号之外，反斜杠会转义紧随其后的字符。引号包围的空参数会被保留。
未加引号或双引号中的 `${NAME}` 会展开；单引号或转义的美元符号会保留字面量。
`$NAME` 保持字面量。不进行通配符展开、波浪号展开或命令替换。
未加引号且未转义的 `|` 分隔管道段，两侧可以没有空格。空段（包括 `||`）会导致错误。
除下述精确的尾部重定向标记外，未加引号的 `&`、`;`、`<`、`>`、反引号和圆括号
会导致错误。如需将这些字符作为普通参数传入，请加上引号或进行转义。

任意管道段（包括单命令）可在尾部使用 `2>&1`，将 stderr 合并到输出管道，
或使用 `>/dev/null` 丢弃原 stdout。两种标记可以按任意顺序组合，此时仅将 stderr
传给下一段或最终捕获，原 stdout 被丢弃。标记与前面的命令、参数或其他标记之间
必须有空格或制表符，标记内部不接受空白，标记后可以直接接 `|`。
每种标记最多出现一次，标记后不能再接普通参数。完整引用、正确转义的标记及
变量展开产生的标记文本仍是普通参数。字面量 `2>&1` 必须引用或写成 `2\>\&1`，
同时转义两个特殊字符；字面量 `>/dev/null` 可以写成 `\>/dev/null`。
旧写法 `stdout>/null`、`stderr>/stdout`、其他重定向形式及 export 重定向
会产生带文件名和行号的解析错误。

`$ export NAME=value` 每条指令设置一个变量，对同一 Markdown 文档后续指令生效，
可跨代码块；切换文档后重置。变量名必须匹配 `[A-Za-z_][A-Za-z0-9_]*`，
值可以为空或包含额外的 `=`。赋值中的 `${NAME}` 遵循参数的引号和转义规则。
查询优先使用此前的 export，再查询父进程环境；自引用读取赋值前的值，
已导出的空字符串覆盖父环境。Windows 下变量名不区分大小写，导出名和查询键统一
使用 ASCII 大写，因此先赋值 `Name` 再赋值 `NAME` 会覆盖同一个变量；
Linux 和 macOS 下仍区分大小写。展开只进行一次，不重新分词：值中的空格、引号和
`|` 仍属于原参数，空结果也会保留为一个参数。

每个管道段的首个词选择执行目标，禁止在其中展开 `${NAME}`；作为普通参数传入的
文件路径可以展开。未定义变量、非法或未闭合的引用、非法赋值，以及管道中的
`export` 都会产生带文件行号的解析错误。export 不接受预期输出或退出码，
不计入用例数；仅含 export 的代码块合法，但整次运行没有实际用例时仍会报错。
整个文档解析成功后才会执行其中的用例。

````markdown
```mooncram user/foo
$ export NAME='Moon Bit'
$ ./hello.mbtx "${NAME}"
Hello, Moon Bit!

$ cmd/main --version
my-cli * (glob)

$ ./producer.mbtx|cmd/filter|./consumer.mbtx
filtered output
```
````

命令后面的行描述预期输出。默认情况下，每一行都必须精确匹配，包括行尾空格。
末尾的 `[N]` 用于设置预期退出码；未指定时为 `0`。管道匹配最后一段路由后的输出，
默认采用 pipefail：等待所有段结束，全部成功返回 `0`，否则返回管道位置最右侧的非零退出码，
不受完成顺序影响。普通非零状态仍可通过 `[N]` 断言，后续用例继续执行。
任意导入段返回 `255` 或 `-1` 都属于执行错误。负数状态码表示程序被信号终止，
具体值由进程库报告。没有预期输出行意味着路由后的输出必须为空。

代码块开头、结尾或紧邻下一条命令之前的空行用作分隔符。
非空预期输出行之间的空行则属于输出。要显式表示一个空输出行，请使用
`"" (escaped)`，尤其是在输出末尾。
这样就能区分空输出和仅包含一个换行符的输出。

## 文件级工具导入

每份 Markdown 可声明固定版本的 Mooncakes 可执行包：

````markdown
```mooncram-import
moongrep : moonbit-community/moongrep@0.3.5
```

```mooncram
$ moongrep --version
* (glob)
```
````

每份文件允许零个或一个 `mooncram-import` 块。绑定对该文件的所有测试块生效，
包括声明之前的测试块；切换文件后重置。import 不计为用例。
每个非空白行采用 `别名 : 坐标`，允许空白行。空块、重复别名、第二个 import 块和
非法声明均为带源码位置的解析错误；第二个块的错误指出两处声明位置。
围栏规则与测试块相同，支持引用、列表和较长反引号围栏；语言名后不接受配置。

别名区分大小写，采用 `[A-Za-z_][A-Za-z0-9_-]*`，保留 `export`。
坐标采用 `user/module[/package]@version`，路径组件遵循本地包名规则。
版本必须是精确 SemVer，支持预发布和构建标识。省略版本、`latest`、版本范围、
通配符、默认参数及声明中的变量展开均被拒绝。

各管道段独立解析别名，执行 `moonx --target wasm <coordinate> -- <args...>`，
继承原有参数、cwd、export 和重定向。导入工具始终使用 Wasm，即使指定
`--target native`。模块声明块中的别名若与本地可执行候选同名，执行前报错，
要求更换 import 别名；本地配置错误也正常报错。未命中别名的命令遵循本地规则。
远程包仅能通过已声明的别名调用。

仅导入命令将 `255` 和 `-1` 保留为执行错误，包括导入程序自身返回这些状态的情况。
并发监视所有段，任意导入段返回上述状态都会取消并回收其他进程，阻止整份文档
更新预期结果及生成试运行文档差异。其他非零状态仍可断言，并遵循上述 pipefail 规则。
发生错误后仍会继续处理其他文档。

远程下载和缓存由 moonx 管理。moonx 启动后才获取远程资源，因此获取失败前，
其他段可能已经运行并产生副作用。下载与执行共用用例超时；`test`、`update`
和 `update --dry-run` 执行相同流程。

## 匹配与转义

| 后缀 | 含义 |
| --- | --- |
| 无后缀 | 精确匹配整行 |
| ` (glob)` | 整行通配符匹配：`*`、`?`、`[abc]`、`[a-z]`、`[!a-z]`、`[^a-z]`；反斜杠用于转义字符 |
| ` (regex)` | 使用标准库 `Regex` 进行整行匹配 |
| ` (escaped)` | 将 JSON 字符串解码后进行精确匹配，可表示控制字符 |
| ` (no-eol)` | 最后一行输出没有结尾换行符；位于其他后缀之后 |

通配符 `?` 和字符集合匹配单个 Unicode 字符。匹配过程中不会重复或跳过输出行。
未知括号后缀（如 `(equal)`、`(foo)` 或 `(re)`）作为普通文本参与精确匹配。
格式错误的通配符或正则表达式，以及出现在非末行的 `(no-eol)` 都会报错，
并指出文件和行号。要按字面量匹配以已知注解结尾的输出，应使用 JSON 字符串加 `(escaped)`。

`(escaped)` 要求提供完整的 JSON 字符串。它可以表示制表符、回车符、NUL、
ANSI 转义序列，以及看起来像命令、围栏、状态码或匹配后缀的输出。
其中不能包含 LF（换行符）；请改用多个预期输出行。

````markdown
```mooncram
$ ./special.mbtx
"$ this is output" (escaped)
"[2]" (escaped)
"```" (escaped)
"\u001b[31mred\u001b[0m" (escaped)
"" (escaped)
final text (no-eol)
[3]
```
````

输出必须是有效的 UTF-8。比较时会将 CRLF 规范化为 LF；
独立的 CR（回车符）、空行、行尾空格和末尾换行符都会保留。

## 执行行为

围栏后缀仅声明模块；后端与超时仍由 CLI 选项设置。`--target` 为所有本地包用例
选择后端，`--timeout-ms` 为每个用例设置期限；`.mbtx` 脚本仍固定使用 Wasm。构建进程及每个管道段继承
mooncram 的环境，并覆盖该用例对应的文档 export 变量。首段从 stdin 立即读到 EOF；
后续段接收前一段路由后的输出原始字节。

预期结果只与最后一段路由后的输出比较。未重定向的 stderr 会并发排空，按段顺序
拼接，在断言失败时以 `diagnostic stderr` 显示。合并的 stderr 与路由后的 stdout
使用同一根系统管道并参与匹配，不再重复收集到诊断。捕获流都必须是有效 UTF-8，
且当前没有可配置的大小上限。中间管道数据不进行解码或换行规范化。
被丢弃的 stdout 使用固定 8 KiB 字节缓冲区并发排空，不累积或进行 UTF-8 解码，
因此允许包含非法 UTF-8。构建进程始终使用默认路由。

所有本地段的构建预检查完成后才会启动被测程序，各段并发执行，并等待所有段退出。
整个用例共用一个包含构建、远程获取与执行的超时。超时、启动或捕获失败，以及任意
导入段返回 `255` 或 `-1` 时，
会取消所有直接管理的进程并关闭管道，将该用例记为执行错误。
程序必须自行管理其脱离的子进程。测试以当前用户的权限执行代码，
不会在沙箱或隔离的临时工作区中运行。

## 更新预期结果

`update` 只修改未通过的预期结果。通过的用例和仍然匹配的模式会保留原样。
命令、围栏标记、容器前缀（如引用或列表前缀）、周围的正文以及文档的换行符格式都会保留。
特殊输出会被自动转义，缺少末尾换行符和非零退出状态也会被自动表示。

`--dry-run` 会运行相同的命令并显示文档差异，但不会写入 Markdown。
这些命令仍然可能对文件系统产生正常的修改。实际更新和试运行只要成功完成，
都会返回 `0`，即使存在需要修改的内容也是如此。

存在解析、构建或执行错误的文档不会被更新。其他文档仍然可以继续运行和更新。
写入更新之前，mooncram 会检查源文件内容是否发生变化，然后使用同目录下的临时文件
进行原子替换。替换后的文件使用新建文件的权限（`0644`，受 umask 影响）；
当前版本不会保留原文件的权限、inode 标识和扩展文件系统元数据。
